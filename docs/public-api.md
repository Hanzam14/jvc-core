# Public API Separation (0.1.0)

JVC distinguishes **model-facing governed surfaces** from **trusted-host/internal APIs**. Python importability itself is not an agent sandbox: any Python caller that intentionally instantiates low-level internals bypasses mediation by construction. The guarantee is narrower and explicit: **no model-facing surface (CLI, `GovernedExecutor`) exposes raw execution primitives, unvalidated identifiers, or unpinned commands.**

---

## A. Model-Facing Governed API

Safe for tool-calling agents to invoke (all enforcement happens inside):

- CLI: `jvc route`, `jvc validate-routes`, `jvc demo`, `jvc --version/--help`.
  Deferred (not in 0.1.0): `jvc serve`, `jvc check`.
- `GovernedExecutor`: `project_status`, `fs_write`, `fs_rollback`, `recover`,
  `git_status`, `git_diff`, `git_log`, `git_stage`, `git_commit`,
  `git_branch`, `run_declared_check`.
  - All filesystem targets pass root containment + secret/control-plane denial.
  - All Git operations pass the effective-configuration audit; mutations are
    serialized under a per-project transaction lock.
  - `run_declared_check` executes only checks from a host-supplied pinned
    manifest (`declared_manifest`), never project-owned content.

## B. Trusted-Host / Internal API

Must only be called by the trusted host/operator process. Importable, but
documented host-only and never exposed through the CLI:

- `jvc.contracts.run_check`, `resolve_runtime`, `load_contract` — execute
  project-owned contract commands; used by the synthetic demo fixtures and
  host tooling only. Project-owned `AGENTS.md` never grants executable
  authority through any 0.1.0 model-facing surface.
- `jvc.execution.runner.run_declared_check` — pinned execution engine; safe
  only with a host-constructed manifest and pinned executables.
- `jvc.policy.guard.PrewriteGuard` — manifest lifecycle with boundary-checked
  entry paths and screened output paths; host-chosen paths.
- `jvc.recovery.store.RecoveryStore` — raw target paths; boundary enforcement
  is the caller's (`GovernedExecutor`) responsibility.
- `jvc.continuity.state.ContinuityManager` — callers must pass validated
  identifiers (`record_decision` rejects path separators/traversal in
  `decision_id`).
- `jvc.policy.authority` key/capability helpers — require host-held secrets;
  `generate_operator_key`/`rotate_operator_key` require explicit
  `forbidden_roots`.
- `jvc.policy.locks.ResourceLock` — primitive; safe lock *names* come from
  `lock_name_for_resource` (canonical identity), enforced inside the
  executor/continuity layers.

## Identifier Hygiene

Identifiers that become filenames are validated before path construction:
`record_decision` accepts only `[A-Za-z0-9][A-Za-z0-9_.-]{0,127}`. Capability
IDs, receipt IDs, and lock names are generated by JVC, never taken from
model input.

## Accidental Execution Surfaces

Audited 0.1.0 subprocess use: fixed-verb Git invocations (executor), pinned
executable + pinned script execution (runner), fixed `icacls` permission call
(authority), and fixture `git init/config` (demo/tests). No `eval`, `exec`,
`os.system`, shell execution, or generic command runner exists in the
package. `contracts.run_check` is the only project-content-driven executor
and is host-only (no CLI path reaches it).
